# 도메인 설계

> 상태: v0.2 (증권사 육성 구조로 개정, 2026-11-05. #292에서 옛 인생 시뮬레이터의 도메인을 지운 뒤)
> 표기: **(확정)** = 대화에서 정해진 것, **(제안)** = 제 판단이며 아직 합의되지 않은 것. 구조는 [architecture.md](./architecture.md), 게임 설계는 [증권사 육성 설계](./superpowers/specs/2026-11-05-brokerage-raising-design.md), 결정은 [decisions.md](./decisions.md) 197번부터를 따른다.

## 1. 분할 기준

도메인은 게임 개념의 이름이 아니라 아래 기준으로 나눈다.

1. **상태 소유권.** 상태를 바꿀 수 있는 도메인은 하나뿐이다. 다른 도메인은 서비스 인터페이스로만 읽거나 요청한다.
2. **같이 바뀌는 것끼리 묶는다.** 같은 이유로 수정되는 규칙은 같은 도메인에 둔다. 육성 판과 회사는 같은 시장·같은 등급표·같은 돈을 쓰므로 한 도메인(육성)에 둔다 (decisions.md 208번).
3. **도메인 사이의 호출을 줄인다.** 다른 도메인을 부르는 것은 **육성 하나**다. 행동·콘텐츠·세션은 혼자 선다 (3절).
4. **서버에 있는 것만 도메인이다.** 화면과 그림은 클라이언트의 일이다 (확정).

모든 도메인은 서버 안의 모듈이다. 모듈형 모놀리스로 가며 MSA 분리는 목표가 아니다 (확정). DB는 **하나의 스키마**를 쓰고, 도메인은 이름 접두사로 자기 테이블을 구분한다 (확정, FK 없음). 접두사는 도메인 이름과 같다 (예: `raising_run`).

## 2. 도메인 목록

| 도메인 | 패키지 | 소유하는 상태 | 책임 | 테이블 |
|---|---|---|---|---|
| 육성 | `raising` | 육성 판, 세션의 육성 기억, 회사 | 3분 육성 한 판과 회사를 조율한다. 카드 구성, 판의 시장, 입사 심사, 등록·배치·결산·공채·인사·매각, 사장 명성 | `raising_run`, `raising_memory`, `raising_company` |
| 행동 | `behavior` | 없음 (순수 규칙) | 선택이 뒤집히는 판정(줏대 → 인내심/용기), 형광펜의 정답 여부(힌트), 운, 판정 한 번의 뒤집힘 확률 | 없음 |
| 콘텐츠 | `content` | 콘텐츠 버전 기록 | `content/` JSON을 서버 시작 때 읽어 검증하고 메모리에 둔다. 조회 | `content_version` |
| 세션 | `session` | 익명 세션 | 발급과 확인, 최근 세션 목록(관리자) | `session_info` |

### 도메인이 아닌 것

| 대상 | 위치 |
|---|---|
| 화면, 그림(사무실·도트 사람), 그림 끄기, PWA | 클라이언트 |
| API 요청·응답 변환, 관리자 토큰, 플레이 로그 | `api` 계층 (도메인 로직을 두지 않는다) |
| 두 도메인 이상이 쓰는 값 타입, 시드 난수, 공통 예외 | `common` |

### 옛 도메인 (기록)

옛 인생 시뮬레이터의 도메인이다. **#292에서 코드를 지웠다** (decisions.md 227번). 스펙은 [specs/](./specs/README.md)에 기록으로 남고, 테이블은 DB에 남아 있지만 코드가 쓰지 않는다 ([db.md](./db.md) 2절).

| 도메인 | 맡던 것 | 지금 어디로 |
|---|---|---|
| 진행 (`progress`) | 판 조율, 시각 보고, 나이로 종료 | 조율은 육성이 맡는다. 시계와 나이는 없다 |
| 캐릭터 (`character`) | 능력치, 성장, 직업, 성향 | 능력치·성장·성향은 육성 판의 상태(JSON)에 있다. 직업은 없다 |
| 자산 (`asset`) | 현금, 보유, 빚, 장부 | 육성 판의 상태(JSON)에 있다 |
| 시장 (`market`) | 종목 가격과 월별 이력 | 카드 한 장 = 한 분기로 육성이 굴린다 (decisions.md 205번) |
| 이벤트 운영 (`event`) | 이벤트 발생, 선택지, 숨은 값 | 카드 구성은 육성이 정한다 |
| 가계 (`household`), 주거 (`housing`) | 결혼·자녀·은퇴, 집 | 없다 (증권사 육성 설계 3.2절) |
| 결과 (`result`) | 판 결과, 순위표, 공유 | 끝난 판은 `raising_run`에 남는다. 순위표·공유는 없다 |

## 3. 도메인 사이의 호출 규칙 (확정, `DomainBoundaryTest`)

```
api ─→ 세션 (확인, 관리자 세션 목록)
   └─→ 육성 ─→ 행동
             └→ 콘텐츠
```

- **육성만 다른 도메인(행동·콘텐츠)을 쓴다.** 행동·콘텐츠·세션은 다른 도메인을 부르지 않는다.
- 어느 도메인도 다른 도메인의 `internal` 패키지를 쓰지 않는다.
- `api`는 육성과 세션의 공개 타입만 쓴다.
- 도메인과 `common`은 `api`를 모르고, `common`은 어떤 도메인에도 의존하지 않는다.

행동은 능력치와 판정 상황을 **입력으로 받아 결과를 돌려주는 순수 함수**라 단독으로 개발·테스트할 수 있다. 콘텐츠는 읽기만 한다. 세션은 세션 ID만 알고 육성 판을 모른다. 육성 판과 회사는 세션 ID로 세션에 묶인다.

### 처리 흐름 1: 카드에 선택 내기 (`POST /api/runs/{runId}/choose`)

1. `api`가 세션 쿠키를 세션 도메인으로 확인해 세션 ID를 얻는다.
2. 육성이 세션의 진행 중인 판을 잠그고(`FOR UPDATE`) 읽는다. 카드 번호가 지금 카드와 다르면 400이다.
3. 뉴스 카드면 육성이 행동에 `(선택, 능력치, 꼬드김의 분위기, 보유 여부, 장치가 막은 판정, 난수)`를 넘겨 **실제 행동과 원인**을 받는다.
4. 육성이 매매·가격 변동·운·성장을 반영하고, 형광펜과 단서 기사는 행동의 힌트와 콘텐츠의 문장으로 다음 카드를 펼친다.
5. 육성이 판 상태와 세션 기억을 저장하고 "고른 것 → 실제, 원인, 손익"과 다음 카드를 돌려준다. 마지막 카드(입사 심사)면 판이 끝난다.

### 처리 흐름 2: 회사 결산 (`POST /api/company/settle`)

1. 육성이 세션의 돌고 있는 회사를 잠근다. 공채 판이 남아 있으면 400이다.
2. 직원마다 자리에 맞게 판단을 굴린다. 판정 확률은 행동의 `flipChanceBp`로 육성 판과 같은 규칙을 쓴다 (decisions.md 211번).
3. 수수료·운용 손익·연봉으로 자본을 바꾸고, 회사 등급·자리 수·직원 등급을 다시 매긴다.
4. 다음 해 연초 회의(조짐, 올해 필요한 인재)를 준비한다. 시대의 마지막 해면 회사가 끝나 매각을 기다린다.

## 4. 도메인별 요약

### 육성 (`raising`)

- 공개 인터페이스는 둘이다. **`RaisingService`**(판 시작·조회·카드 선택, 관리자용 최근 판 목록)와 **`CompanyService`**(회사 조회, 등록, 배치, 결산, 인사 공채, 매각).
- 규칙은 `internal`의 `RunEngine`(카드 한 장)과 `CompanyEngine`(결산)에 있다. 저장·잠금·조율은 `DefaultRaisingService`·`DefaultCompanyService`가 한다.
- **육성 판:** 카드 12장, 카드 수로 끝난다 (decisions.md 197번). 성향 → 실전 매매(뉴스) + 돈이 걸린 큰일 → 입사 심사. 세션의 첫 판은 짜인 판이다 (204번).
- **운용금:** 회사가 없으면 사장의 사재 1억 원, 회사가 돌고 있으면 공채로 회사가 내준다 (199·212번).
- **능력치:** 속은 0~100 점수이고 응답에는 **등급만** 나간다 (206번). 운은 움직이지 않는다.
- **회사:** 첫 육성의 사람을 등록하면 열린다. 한 해 = 연초 회의 → 배치 → 공채 육성(하고 싶을 때만) → 결산 (208번). 공채 판은 그해 회사의 시장에서 한다 (220번).
- **자리:** 자리마다 원하는 능력치가 있다. 돈을 굴리는 자리와 돈을 굴리지 않고 돕는 자리가 있다. 자리 수는 회사 등급이 정한다 (209번). 자리 목록과 효과는 `content/raising.json`의 `company.desks`와 decisions.md(210번부터)를 본다.
- **매각과 명성:** 시대가 끝나면 반드시 팔고, 등급이 조건 이상이면 스스로 팔 수 있다. 팔 때 명성이 오르고 공동창업자를 데려간다 (215~218번). 명성은 회사를 넘어 이어지므로 세션 기억(`raising_memory`)에 둔다.
- 설정은 `application.yml`의 `raising.*`, `raising.company.*`에 있다.

### 행동 (`behavior`)

- 판정 순서: 줏대(꼬드김) → (지켜보기면 인내심, 사기·팔기면 용기). 규칙은 [specs/behavior.md](./specs/behavior.md) 4절이 지금도 유효하다.
- 투자 원칙 장치가 막은 판정은 `ChoiceContext.Guards`로 받는다. 막힌 판정도 난수는 그대로 뽑는다 (decisions.md 198번).
- 뒤집힘의 원인을 항상 결과로 돌려준다. 원인이 보이지 않는 억울함은 이탈로 이어진다 (prd 2절).
- 힌트는 방향·강도·구체성만 정한다. 형광펜을 어느 문장에 긋는지는 육성이 정한다 (decisions.md 200번).
- `flipChanceBp`는 판정 한 번의 뒤집힘 확률이다. 회사 결산이 직원의 판단을 굴릴 때 쓴다.
- 상태가 없으므로 DB 테이블이 없다.

### 콘텐츠 (`content`)

- 원본은 저장소의 `content/` JSON이다 (확정). 서버 시작 때 한 번 읽어 메모리에 두고, 규칙을 어기면 시작 단계에서 실패한다.
- 담는 것: 섹터·스타일(`meta.json`), 종목(`stocks.json`), 뉴스 정의(`news.json`), 단서 기사 문장(`clues.json`), 위기 갈래와 전조(`crises.json`), 형광펜 메모와 꼬드김 문구(`phrases.json`), 육성 카드와 회사 문구(`raising.json`).
- DB에는 어떤 버전이 로드되었는지만 남긴다(`content_version`). 육성 판은 시작할 때의 콘텐츠 버전을 `raising_run.content_version`에 적는다.

### 세션 (`session`)

- 계정 없는 익명 세션이다 (확정). 토큰 원문은 쿠키(`IG_SESSION`)에만 있고 DB에는 해시만 둔다.
- 마지막 접속 후 `session.ttl`(1일)이 지나면 만료된다. 처음·마지막 접속 IP를 남긴다 (decisions.md 63번).
- 만료된 세션의 육성 판·회사를 지우는 정리 작업은 아직 없다.

## 5. 작업 분담 (기록)

> 기록: 옛 인생 시뮬레이터를 처음 만들 때는 구현 에이전트 넷(판정, 시장·이벤트, 플랫폼, 클라이언트)과 진행을 나눠 맡았다. 그 도메인은 #292에서 지웠다. 지금은 도메인이 넷이고 육성 하나가 조율하므로 이 분담을 쓰지 않는다. 도메인 경계는 작업자 수와 무관하게 빌드에서 강제한다.

## 6. 용어집

같은 개념에 이름이 둘 이상 붙지 않도록 고정한다. 화면 말은 쉬운 말로 쓴다 (decisions.md 207번).

| 용어 | 뜻 | 코드 이름 | 쓰지 않는 표현 |
|---|---|---|---|
| 사장 | 플레이어. 사람을 키우고 회사에는 배치만 한다 | - | - |
| 육성 판 | 사람 한 명을 키우는 3분 한 판. 카드 12장으로 끝난다 | `run` | 게임, 인생, 라운드 |
| 카드 | 육성 판의 한 장. 성향·뉴스·원칙·풀기·큰일·빚내서 사기·입사 심사가 있다. 한 장이 시장의 한 분기다 | `CardKind` | 이벤트, 장면 |
| 수습 기간 | 육성 판의 진행 표시 "수습 기간 n / 12". 나이 대신 쓴다 | - | 나이 |
| 운용금 | 육성 판에서 굴리는 돈. 사재 1억 원 또는 공채로 회사가 내준 돈 | `fund` | 초기 자산 |
| 선택 | 사용자가 누른 사기·팔기·지켜보기 | `Action` | 입력, 명령 |
| 실제 행동 | 판정을 거쳐 실제로 일어난 행동 | `actual` | 최종 선택 |
| 손이 뒤집힘 | 선택과 실제 행동이 다른 것. 코드 이름은 이탈 | `Deviation`, `flips` | 오버라이드 |
| 지켜본다 | 사지도 팔지도 않는 선택 | `HOLD` | 관망(화면), 홀드 |
| 꼬드김 | 줏대 판정. 단골 인물이 "다른 뉴스"를 들고 온다 | `sway`, `tempter` | - |
| 단서 기사 | 뉴스 카드의 기사. 결정적 문장 하나와 곁가지·중립 문장으로 짠다 | `clues` | 뉴스 본문 |
| 형광펜 | 안목만큼 맞는 표시. 결정적 문장 또는 반대쪽 곁가지에 긋는다 | `Hint` | 팁, 예측 |
| 투자 원칙 장치 | 같은 능력치로 두 번 뒤집히면 권하는 장치. 판정을 막고 대가가 있다 | `device` | - |
| 폭락 조짐 | 위기 앞에 뜨는 빨간 글씨 | `omen` | 전조(화면) |
| 등급 | F < E < D < C < B < A < S < SS < SSS < X < XX < XXX < Z < ZZ < ZZZ. 사람·회사·사장 모두 쓴다. 능력치는 SSS까지 | `StatGrade` 등 | 점수(화면) |
| 종합 등급 | 다섯 능력치 평균의 등급. SSS 위(X~ZZZ)는 실전 경험으로 오른다 | `overallGrade`, `rank` | - |
| 실전 경험 | 회사에서 위기를 버틸 때 쌓이는 경험. 능력치 성장의 경험치와 다르다 | `experience` | - |
| 입사 심사 | 육성 판의 마지막 카드. 종합 등급을 매기고 등록을 정한다 | `EXAM` | 엔딩, 결과 화면 |
| 회사 | 사장의 증권사. 한 해씩 턴으로 돈다. 등급은 자본으로 매긴다 | `company` | - |
| 직원 | 회사에 등록한 사람 | `Employee` | 캐릭터 |
| 자리 | 직원을 앉히는 곳. 자리마다 원하는 능력치가 있고, 돈을 굴리는 자리와 돕는 자리가 있다. 자리 수는 회사 등급이 정한다 | `desk` | 슬롯 |
| 배치 | 직원을 자리에 앉히는 것. 사장이 하는 유일한 경영이다 | `placement` | - |
| 공채 | 회사가 운용금을 내주고 하는 육성 판. 한 해에 한 번, 하고 싶을 때만 한다 | `recruit` | - |
| 인사 직원 | 인사팀 자리의 직원. 육성 없이 신입을 데려온다 | `hr` | - |
| 연초 회의 | 한 해의 시작. 조짐과 올해 필요한 인재를 본다 | `Meeting` | - |

| 시대 | 회사마다 다른 시장 조건(한 해 시장 갈래의 비중, 자리별 보너스). 세 해로 끝나고 회사를 판다 | `era` | - |
