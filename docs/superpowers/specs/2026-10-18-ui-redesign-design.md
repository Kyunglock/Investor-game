# 설계: 화면 전면 개편 — '80억 분의 1' 톤, 도트 캐릭터, 인생 기록

> 작성: 2026-10-18 · 상태: 합의됨 (구현 전) · 근거: [architecture.md](../../architecture.md) 7·8절, [decisions.md](../../decisions.md), [specs/README.md](../../specs/README.md)
> 목업: [mockup-game-screen.html](./2026-10-18-ui-redesign/mockup-game-screen.html), [mockup-character-system.html](./2026-10-18-ui-redesign/mockup-character-system.html) (브라우저로 열면 보인다. 도트 그림은 거칠게 찍은 자리표시자이며 조합 원리와 배치만 기준이다.)
> 표기: **(확정)** 사용자가 정함 · **(내 결정)** 작성자가 정했고 사용자가 뒤집을 수 있음 · **(빌더)** 구현하는 쪽이 정함

## 1. 의도

지금 화면은 파란 버튼과 흰 카드뿐인 기본 Tailwind 모양이라 "전체적인 느낌이 구리다"는 게 사용자의 평가다. 참고로 삼은 것은 브라우저 인생 시뮬레이션 **'80억 분의 1'**(1in8b.life)이다. 그 게임의 **색감·글꼴·도트 그림 쓰임새**를 가져오고, **별명에 따라 생김새가 다르고 나이 들수록 바뀌는 도트 캐릭터**를 둔다. 진행 방식(시간이 저절로 흐르고 선택이 뜨면 멈춤)은 바꾸지 않는다.

화면에 보이는 것은 전부 서버 데이터에서 나와야 하므로, 목업에 있지만 서버가 아직 주지 않는 두 가지(**인생 기록**, **연간 자산**)를 서버에 더한다. 사용자가 "같이 가자"고 확정했다.

## 2. 목표 · 비목표 · 하면 안 되는 것

**목표**
- '80억 분의 1'처럼 **차분한 문서·기록부 느낌**의 화면. 종이빛 바탕, 와인 레드와 청록 포인트, 명조 제목, 고딕 본문, 모노 숫자.
- 도트는 **그림(캐릭터, 장면)에만**. 글자와 UI는 깔끔하게 **(확정)**. 픽셀 폰트는 쓰지 않는다 **(내 결정, 사용자가 A/A+ 중 답하지 않아 A로 정함)**.
- 캐릭터는 **나이 몸통 × 강점 머리장식 × 약점 표시** 세 겹을 포개서 만들고, **신원 카드(얼굴)와 가운데 장면(전신)** 두 곳에 보인다 **(확정)**.
- 인생 기록(시간순 사건), 인생 지도(한 칸 = 1년), 자산 곡선을 서버 데이터로 그린다.
- 탄생 화면은 '출생 신고서', 결과 화면은 '인생 기록부' 모양의 문서로.
- 모바일(360px) 우선은 유지한다 (decisions.md 20번).

**비목표**
- 게임 규칙, 이벤트 내용, 밸런스는 건드리지 않는다.
- 시간 배속 단계(현재 1×·2×)는 바꾸지 않는다. 목업의 4×는 장식이다.
- '80억 분의 1'의 기능(자동 결정, 카운트다운, 생각 남기기, 추모관, 통계)은 가져오지 않는다.
- 소리, 음악은 없다.

**하면 안 되는 것 (anti-goals)**
- **레트로 UI 금지.** 픽셀 폰트, 각진 두꺼운 테두리, 격자 바탕, 깜빡이는 커서 같은 것. 사용자가 보고 "너무 레트로다"라며 되돌렸다 **(확정)**.
- 클라이언트에 게임 규칙이나 숨은 값을 두지 않는다 (architecture.md 7절). 화면 문구는 클라이언트가 만들되, **사실(숫자, 코드, 순서)은 서버에서** 온다.
- 지어낸 상황 문단("올해의 상황") 같은, 서버 사실에 근거 없는 서술을 넣지 않는다.
- 다른 도메인 테이블을 읽거나 조인하지 않는다 (decisions.md 16번).

## 3. 제약

- 스택 그대로: React, Vite, Zustand, Tailwind v4, openapi-fetch (web). Spring Boot, JdbcTemplate, Flyway (server). 계약은 `contracts/openapi/game.yaml`이 먼저다.
- 소유권: 클라이언트는 `web/**`(agent4), 진행 도메인과 `api/**`는 agent5, 계약과 의존성 추가는 통합 담당 (architecture.md 8절). 이 설계는 **진행·계약·클라이언트만** 건드리고 캐릭터·자산·이벤트·행동·콘텐츠·결과 도메인은 바꾸지 않는다.
- 새 테이블은 `progress_*` 접두사만 (db.md 6절).
- 기존 E2E 테스트의 `data-testid`(`age`, `nickname`, `total-asset`, `cash`, `job`, `style`, `stat-*`, `event-card`, `hint`, `outcome-card`, `outcome-actions`, `outcome-message`, `birth-reveal`, `reveal-*`, `reveal-nickname`, `result-screen`, `reported-day`)는 유지한다. 새 요소에는 새 id를 붙인다.
- `prefers-reduced-motion`이면 모든 움직임을 끈다 (기존 규칙).
- 글꼴은 CDN이 아니라 npm 패키지(`@fontsource/noto-serif-kr`, `@fontsource/noto-sans-kr`, `@fontsource/jetbrains-mono`)로 넣는다 **(내 결정: 오프라인·재현성)**. 의존성 추가는 통합 담당이 한다.

## 4. 시각 체계 (확정, 세부 값은 내 결정)

### 4.1 색

CSS 변수로 `web/src/index.css`에 둔다. 다크 모드는 없다.

| 변수 | 값 | 쓰임 |
|---|---|---|
| `--bg` | `#f3f4f3` | 페이지 바탕 (종이빛 회색) |
| `--card` | `#ffffff` | 카드 |
| `--line` | `#d7dcd8` | 카드 테두리 |
| `--line-soft` | `#e8ebe8` | 표 구분선, 막대 바탕 |
| `--ink` | `#1d2626` | 본문 글자 |
| `--muted` | `#6f7a78` | 보조 글자 |
| `--faint` | `#a3adaa` | 라벨, 캡션 |
| `--wine` | `#8b2342` | 주 포인트: 신원 카드 머리띠, 주 버튼, 결정 표시, 현재 칸 |
| `--wine-soft` | `#f7e6ea` | 선택된 선택지 바탕 |
| `--teal` | `#2e7465` | 보조 포인트: 능력치 막대, 인생 지도 칸, 성장 표시, 힌트 상자 선 |
| `--teal-soft` | `#e2f0ea` | 강조 행 바탕, 힌트 상자 |
| `--gold` | `#b2862b` | 약점 능력치 막대 |
| 상승 / 하락 | `#c0392b` / `#2d5fa6` | 주가·손익 (한국식 빨강 상승, 파랑 하락. 기존 유지) |

막대 색 규칙: 강점 능력치는 `--wine`, 약점 능력치는 `--gold`, 나머지는 `--teal`.

### 4.2 글꼴

| 역할 | 글꼴 | 굵기 |
|---|---|---|
| 큰 제목, 이름, 나이 숫자, 결정 카드 제목 | Noto Serif KR | 900 |
| 본문, 라벨, 버튼 | Noto Sans KR | 400 / 700 |
| 금액, 퍼센트, 능력치 숫자, 일련번호, 나이 라벨, 배속 버튼 | JetBrains Mono | 400 / 600 |

기준 본문 14px, 줄 간격 1.55. 라벨 11~12px `--faint`.

### 4.3 모양

- 카드: 흰 바탕, 1px `--line` 테두리, 모서리 6px, 그림자 `0 1px 2px rgba(0,0,0,.03)`. 안쪽 여백 14~16px.
- 카드 제목: 15px 700, 오른쪽에 11px `--faint` 보조 설명 (예: "0–100", "한 칸 = 1년").
- 버튼: 주 버튼은 `--wine` 바탕 흰 글자, 보조 버튼은 흰 바탕 1px 테두리. 모서리 4px. 터치 대상 최소 44px (decisions.md 20번).
- 막대: 높이 8px, 모서리 2px, 바탕 `--line-soft`.
- 둥근 알약 모양, 큰 그림자, 파란색은 쓰지 않는다.

### 4.4 움직임 (내 결정)

전부 CSS 전환·키프레임, 각 0.2~0.5초, `ease-out`. 과하지 않게.

| 어디 | 무엇 |
|---|---|
| 카드·문서 첫 등장 | 아래서 8px 올라오며 나타남 (기존 `animate-reveal` 유지) |
| 능력치 공개 | 숫자 0→값 올라감 + 막대 차오름 (기존 유지) |
| 인생 기록 새 줄 | 맨 위에 끼어들며 높이와 투명도 전환 |
| 인생 지도 새 칸 | 칸이 채워질 때 `--teal`로 번짐 |
| 손익 | 결과 카드의 금액이 빨강/파랑으로 한 번 깜빡 (0.6초) |
| 캐릭터 대기 | 2프레임(눈 깜빡임) 3초 주기 |
| 약점 표시 떨어짐 | 약점이 바뀌는 순간 표시가 아래로 떨어지며 사라짐 (0.5초) |
| 결정 카드 등장 | 배경 어두워짐 + 카드 위로 올라옴 |

## 5. 화면 (확정된 배치, 세부는 목업 참고)

### 5.1 상단 바 (모든 화면 공통)

한 줄: `투자자 시뮬레이터` (명조, "시뮬레이터"는 `--wine`) · 나이 `31세` (명조 30px) · 보조 줄 `2056년 · {별명} · 1년 ≈ {n}초` 와 그 아래 65세까지의 가는 진행 막대 · 오른쪽에 `❚❚ 멈춤 / ▶ 계속`, `1×`, `2×`, `다시 시작`.

- 연도는 `2025 + (나이 − 1)`로 표시한다 **(내 결정: 탄생 연도 2025 고정, 서버 값 아님, 순전히 장식)**.
- 선택 카드나 결과 카드가 떠 있을 때 배속·멈춤 버튼은 비활성(흐리게)으로 둔다. 숨기지 않는다 (지금은 숨김).
- 탄생·결과 화면에서는 배속 묶음을 숨기고 제목만 보인다.

### 5.2 진행 화면: 3단

데스크톱(≥ 1024px) `280px · 1fr · 300px`. 태블릿(≥ 768px) 2단(왼쪽 + 가운데, 오른쪽은 가운데 아래로). 모바일 1단, 순서: **장면 → 선택/결과 카드 자리 → 신원 카드 → 능력치·자산 → 인생 기록 → 보유 종목 → 인생 지도 → 자산 곡선**.

**왼쪽**
1. **신원 기록 카드**: `--wine` 머리띠(`신원 기록 · KOR` / 탄생 연도), 아바타(64px, 4.6절의 얼굴 스프라이트), 이름 자리에 **별명**(명조), 아래 표: 단계, 직업, 월급, 투자 스타일, 관심 섹터. 하단에 여권 MRZ 모양 장식 두 줄(모노, `--faint`). MRZ 내용은 별명의 강점·약점 코드와 나이로 만든 장식 문자열 **(빌더)**.
2. **능력치 카드**: 5개 막대(안목·인내심·용기·줏대·운), 오른쪽에 모노 숫자. 아래에 `약점: {능력치} — {weaknessEffect}` 한 줄(`--wine`). 하단 구분선 아래 총자산·현금(모노 14px).

**가운데**
1. **장면 카드**: 64×20 도트 장면(4.7절), 아래 캡션 한 줄 `서울 · {장소} · {상태}`. 캡션은 단계·직업·나이로 클라이언트가 고른다 **(빌더가 문구 표 작성)**.
2. **선택/결과 카드 자리**: 대기 중인 이벤트가 있으면 **결정 카드**(5.3절), 결과가 있으면 **결과 카드**(5.4절), 둘 다 없으면 이 자리는 비운다 (지금의 "시간이 흐르고 있습니다…" 점선 상자는 없앤다. 흐르는 것은 상단 나이와 진행 막대로 보인다).
3. **인생 기록 카드**: 최근 순 목록(5.5절). 제목 오른쪽에 `최근 순`.

**오른쪽**
1. **보유 종목 카드**: 섹터·금액 표 + 마지막 줄 현금. 보유가 없으면 카드 자체를 숨긴다 (지금 규칙 유지).
2. **인생 지도 카드**: 13열 격자, 1세부터 65세까지 65칸. 지난 해는 채움(그 해 총자산이 전년보다 늘었으면 `--teal`, 아니면 `#7fb3a5`; 24세 전은 자산 변동이 없으니 연한 색), 현재 나이는 흰 바탕에 `--wine` 테두리, 65세 칸은 `--faint` 테두리. 범례 두 줄.
3. **자산 곡선 카드**: 인라인 SVG. x축 나이(1, 24, 현재, 65), y축 총자산(만원). 지나온 구간은 `--teal` 실선, 현재 점은 `--wine`, 앞으로는 선 없음 (목업의 점선 예측은 넣지 않는다 **(내 결정: 근거 없는 예측)**). 데이터는 `Game.yearly`.

### 5.3 결정 카드 (선택형 이벤트)

가운데 칸 안에 뜨되, 뉴스일 때는 화면 전체를 `rgba(30,40,40,.45)`로 어둡게 하고 카드를 가운데 띄운다(목업처럼). 직업·성향·제안은 어둡게 하지 않고 칸 안에 그냥 그린다 **(내 결정: 뉴스만 '중대 결정' 느낌)**.

- 머리: 왼쪽 `--wine` 11px 700 `뉴스 · {섹터}` (종류 라벨은 기존 `KIND_LABELS`), 오른쪽 모노 `{나이}세 · {연도}년`.
- 제목 명조 22px, 본문 13px.
- 뉴스: 힌트 상자(`--teal-soft`, 왼쪽 3px `--teal` 선, 모노 12px, 앞에 `힌트 ·`), 다른 뉴스 상자(왼쪽 3px `--line` 선, 위에 10px `다른 뉴스`).
- 선택지: 뉴스는 3열(매수·관망·매도), 나머지는 1열. 버튼은 흰 바탕 1px 테두리 14px 700, 아래 작은 모노 보조(매수: `현금 {금액}`, 매도: `보유 {금액}`). 누르면 `--wine-soft` 바탕 `--wine` 테두리로 바뀌고 요청이 간다. 매도 불가는 기존대로 비활성.
- 바닥 11px `--faint`: `선택은 당신이 하지만, 실행은 당신의 성격이 합니다.`
- 카운트다운, 자동 결정은 없다 (시계가 멈춰 있다).

### 5.4 결과 카드

기존 `OutcomeCard` 내용 그대로, 모양만 4절에 맞춘다. 뒤집힘(`deviated`)은 `--wine`, 성장은 `--teal`, 손익은 빨강/파랑. 버튼 `계속`은 `--wine` 주 버튼. 뉴스 결과이면 어두운 배경 위 카드로, 아니면 칸 안에.

### 5.5 인생 기록

각 줄: 왼쪽 모노 11px `{나이}세`, 오른쪽 13px 본문. 줄 종류별 표시:

| 종류 | 모양 | 문구 (클라이언트가 만든다) |
|---|---|---|
| `BIRTH` | `--teal-soft` 바탕, `탄생` 테두리 알약 | `{연도}년, 안목 62 · 인내심 81 · … 을 타고났다. 별명은 '{별명}'.` |
| `TRAIT` | 앞에 `▸` (`--wine`) | `{질문 제목} · 결정: {고른 선택지 라벨}` |
| `JOB` | 보통 | `{직업}에 취직했다. 첫 월급 {금액}.` |
| `STYLE` | 보통 | `투자 스타일이 '{스타일}'로 굳었다.` (성향 확정 시점) |
| `OFFER` | `제안` 알약 | `{제안 제목} · {고른 선택지 라벨}` |
| `NEWS` | 앞에 `▸`; 뒤집혔으면 `--teal-soft` 바탕 | `{뉴스 제목} · 선택 {매수} → 실제 {관망} ({능력치} 부족)` 뒤집히지 않았으면 `· {매수}` 만 |
| `PRICE` | 보통 | `{섹터} 주가 ▲ 4.2% · 손익 +1,240,000원` (손익 0이면 손익 생략) |
| `GROWTH` | `--teal` 글자 | `경험으로 {능력치} {before} → {after} ↑` |
| `END` | `--wine-soft` 바탕 | `{나이}세, 투자 인생을 마쳤다. {초기} → {최종} ({수익률})` |

문구는 `labels.ts`에 둔다. 서버는 코드와 숫자만 준다 (6절).

### 5.6 탄생 화면: 출생 신고서

가운데 한 장의 문서(최대 폭 640px). 구조는 '80억 분의 1'의 출생 신고 화면을 따른다.

- `--wine` 머리띠: 왼쪽 `출생 신고`, 오른쪽 모노 `No. KOR-{연도}-{gameId 앞 7자}`.
- `이름` 라벨 아래 **별명**(명조 32px). 공개가 끝나기 전에는 `타고난 성격을 정하는 중…` 자리표시.
- 한 줄 설명: `{연도}년, 능력치 5개와 통장 {금액}을 가지고 태어났습니다.`
- 능력치 5줄: 기존처럼 0.7초 간격으로 하나씩 공개, 숫자 올라감 (기존 `BirthReveal` 로직 유지). 공개되지 않은 줄은 `?`.
- 다 공개되면: 아바타(아기 스프라이트) + `약점: …` 한 줄(`--wine`) + `--teal-soft` 안내 상자 `선택은 당신이 하지만, 실행은 당신의 성격이 합니다.` + 주 버튼 `삶을 시작하기`.
- 바탕에 아주 옅은 겹친 곡선 무늬(SVG, `--line-soft` 5% 투명) **(빌더, 생략 가능)**.
- 기존 `data-testid`(`birth-reveal`, `reveal-*`, `reveal-nickname`)와 버튼 역할은 유지.

### 5.7 결과 화면: 인생 기록부

같은 문서 양식. 머리띠 `인생 기록부`. 이름(별명) · 노년 스프라이트 · `{초기} → {최종} ({수익률})` 명조 큰 글자 · 직업·스타일 한 줄 · 최종 능력치 5칸 · `내 선택이 뒤집힌 횟수` 알약들 · **자산 곡선 전체(1→65세)** · **인생 지도 전체** · 주 버튼 `다시 태어나기`. 인생 기록 전체도 접힌 상태로 아래에 둔다 (`<details>`).

### 5.8 시작 전 화면 (`status === 'none'`)

문서 한 장: 명조 큰 제목 `투자자 시뮬레이터`, 두 줄 설명(지금 문구 유지), 주 버튼 `태어나기`. 아래에 5종 강점 아바타가 나란히 (청년 몸통, 장식만 다름) — 캐릭터 체계를 미리 보여 준다 **(내 결정, 생략 가능)**.

## 6. 서버 추가: 인생 기록과 연간 자산 (진행 도메인)

### 6.1 원칙

- 진행(agent5)은 매 사건을 조율하면서 이미 모든 사실을 안다. 그래서 다른 도메인 테이블을 읽지 않고 **진행이 자기 테이블에 기록한다** **(내 결정; 도메인 경계 규칙 준수)**.
- 숨은 값(방향·변동 폭)은 절대 기록하지 않는다. 기록하는 것은 사용자에게 이미 보여 준 사실뿐이다.
- 문구는 기록하지 않는다. 코드와 숫자만.

### 6.2 테이블

```sql
-- V2026101800NN__progress_log.sql
CREATE TABLE progress_log (
    id         BIGINT      GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    game_id    UUID        NOT NULL,
    game_day   INTEGER     NOT NULL,
    kind       TEXT        NOT NULL,   -- BIRTH, TRAIT, JOB, STYLE, OFFER, NEWS, PRICE, GROWTH, END
    payload    JSONB       NOT NULL,   -- 종류별 필드 (6.3절)
    created_at TIMESTAMPTZ NOT NULL
);
CREATE INDEX progress_log_game_idx ON progress_log (game_id, id);

CREATE TABLE progress_year (
    game_id     UUID   NOT NULL,
    age         SMALLINT NOT NULL,      -- 이 나이를 마친 시점
    total_asset BIGINT NOT NULL,
    cash        BIGINT NOT NULL,
    PRIMARY KEY (game_id, age)
);
```

### 6.3 기록 시점과 payload

| 시점 (진행이 이미 처리하는 곳) | kind | payload |
|---|---|---|
| `start` | `BIRTH` | `{ stats: {insight,…}, initialAsset }` |
| `choose` 성향 | `TRAIT` | `{ eventTitle, optionCode, optionLabel }` |
| `choose` 직업 | `JOB` | `{ jobCode, jobTitle, monthlySalary }` |
| 성향이 확정되어 스타일이 정해질 때 | `STYLE` | `{ styleCode, styleName }` |
| `choose` 제안 | `OFFER` | `{ eventTitle, optionCode, optionLabel, accepted }` |
| `choose` 뉴스 (판정 후) | `NEWS` | `{ eventTitle, sectorCode, sectorName, chosen, actual, deviations: [{statCode, from, to}], trade: {status, amount} \| null }` |
| 같은 `choose` 에서 주가 반영 후 | `PRICE` | `{ sectorCode, sectorName, direction, changeBp, pnl, lossSoftened }` |
| 같은 `choose` 에서 성장이 있으면 (능력치마다 한 줄) | `GROWTH` | `{ statCode, before, after }` |
| 판 종료 | `END` | `{ finalAge, initialAsset, finalAsset, returnBp }` |

`ChoiceTicket`에는 이벤트 제목과 선택지 라벨이 없다. `choose`에서 `prepareChoice` 전에 `EventService.pending(gameId)`가 주는 `EventView`(`title`, `options[code,label]`)를 읽어 payload를 채운다. 이벤트 도메인은 바꾸지 않는다 (검토에서 확인).

`progress_year`는 `advance`에서 보고된 일수가 연 경계를 넘을 때마다 한 줄씩 넣는다. 한 번의 보고가 최대 360일(`max-skip-days`)이므로 한 번에 넘는 경계는 최대 하나다. 값은 경계를 넘는 그 요청에서 월급을 넣은 **뒤**의 총자산·현금이다. 같은 나이에 두 번 넣지 않는다 (PK). 판 종료 시 65세 줄도 넣는다.

`deleteByGame`(세션 만료 정리)은 아직 진행에 없다. 생기면 이 두 테이블도 지운다. 이 설계 범위 밖이다.

### 6.4 계약 변경 (`contracts/openapi/game.yaml`)

`Game`에 두 필드를 더한다 **(내 결정: 별도 엔드포인트 대신 포함. 판 하나의 기록은 100줄 안쪽이라 매 `advance` 응답에 실어도 작고, 클라이언트 동기화 버그가 없다)**.

```yaml
Game:
  properties:
    log:
      type: array
      description: 시간순(오래된 것 먼저). 화면은 뒤집어서 최근 순으로 보인다
      items: { $ref: '#/components/schemas/LogEntry' }
    yearly:
      type: array
      description: 마친 나이별 자산. 나이 오름차순
      items:
        type: object
        required: [age, totalAsset, cash]
        properties:
          age: { type: integer }
          totalAsset: { type: integer, format: int64 }
          cash: { type: integer, format: int64 }
LogEntry:
  type: object
  required: [seq, day, kind, payload]
  properties:
    seq: { type: integer }
    day: { type: integer }
    kind: { type: string, enum: [BIRTH, TRAIT, JOB, STYLE, OFFER, NEWS, PRICE, GROWTH, END] }
    payload: { type: object, additionalProperties: true, description: 종류별 필드. 6.3절 }
```

`required`에 `log`, `yearly`를 넣는다. 종류별 payload의 TypeScript 타입은 클라이언트가 `web/src/features/game/log.ts`에 손으로 두고 좁힌다 **(빌더)**.

## 7. 캐릭터 체계 (확정)

### 7.1 구성

세 겹을 포개서 한 스프라이트(16×20 격자)를 만든다. 그림은 **문자 지도 + 팔레트**로 코드에 둔다 (`web/src/features/game/pixel/`), 이미지 파일은 쓰지 않는다 **(내 결정: 조합이 코드이므로 diff와 테스트가 쉽다)**.

| 겹 | 종류 | 결정 근거 |
|---|---|---|
| 몸통 | 아기 1~6세 · 어린이 7~13세 · 청년 14~39세 · 중년 40~64세 · 노년 65세 | 화면의 현재 나이 (`ageAt`) |
| 강점 머리장식 | 족집게(안목) 동그란 안경 · 돌부처(인내심) 감은 눈+염주 · 불도저(용기) 안전모 · 소신파(줏대) 머리띠 · 행운아(운) 네잎클로버 | `nickname(initialStats).strength` — 평생 안 바뀜 |
| 약점 표시 | 눈치 없는(안목) 물음표 · 성질 급한(인내심) 화 자국 · 겁 많은(용기) 식은땀 · 귀가 얇은(줏대) 큰 귀 · 운 없는(운) 비구름 | **현재** `stats`에서 가장 낮은 능력치. 성장으로 바뀌면 표시가 떨어지는 연출 (4.4절) |

특별 별명: `타고난 투자 천재` 왕관, `앞날이 험난한 사람` 반창고, `무난한 보통 사람` 장식 없음. 이 셋은 약점 표시도 없다.

중년은 머리에 흰머리 섞임과 넥타이, 노년은 흰머리·굽은 허리·지팡이. 세부 도트는 **(빌더)** — 목업보다 훨씬 다듬어야 한다. 16×20에서 얼굴 표정이 읽히고, 다섯 강점이 한눈에 구분되면 된다.

### 7.2 쓰이는 곳

- 신원 카드: 얼굴만 (몸통 윗부분 16×10 잘라 64px로).
- 장면: 전신, 장면 격자 안에 배치.
- 출생 신고서: 아기 전신. 결과: 노년 전신. 시작 전 화면: 청년 5종.

약점 판정이 동점이면 `STAT_KEYS` 순서에서 앞의 것 (기존 `nickname` 규칙과 같게, 같은 함수를 쓴다).

## 8. 장면 (가운데 도트 그림)

64×20 격자, 카드 폭에 맞춰 늘린다(`image-rendering: pixelated`). 하늘·배경·바닥 3층 + 소품 + 캐릭터 전신.

| 조건 (위에서부터 먼저 맞는 것) | 장면 |
|---|---|
| 아기 | 집 안, 아기 침대, 창문 |
| 어린이 | 학교 운동장 또는 교실 (성향 질문 시기) |
| 청년, 직업 없음 | 동네 길, 전봇대 |
| 직업 있음, 투자 전 (`SAVING`) | 사무실, 책상, 모니터에 문서 |
| 투자 중 (`INVESTING`) | 원룸, 책상, 모니터에 주가 선 (목업과 같음) |
| 중년 | 같은 원룸이되 소품 더 (책장, 화분) |
| 노년 / 종료 | 집, 창가 의자 |

캡션 문구 표는 **(빌더)**. 시간대(낮·밤)로 하늘 색을 바꾸는 것은 선택 사항 **(빌더)**.

- `progress_log` 기록을 `DefaultProgressService` 안 어디에 끼울지 (각 사건을 처리하는 바로 그 자리).
- 마이그레이션 번호.
- 인생 기록이 길어질 때의 표시(전부 보여 줘도 되고, 30줄 뒤는 `더 보기`로 접어도 된다).

검토에서 정한 작은 결정 **(내 결정)**:
- E2E(`web/e2e/game.spec.ts`)는 버튼 문구로 요소를 찾으므로 새 문구(`멈춤`, `삶을 시작하기`, `다시 시작`)에 맞게 선택자를 고친다. 비활성이지만 보이는 `계속` 버튼 때문에 `.or(eventCard)` 식 선택자는 손본다.
- `progress_year.age`는 "마친 나이"(경계 day = k×360 → age k). 종료 시 `endAge` 줄은 값이 같아도 넣는다. 인생 지도의 1세 칸은 `initialAsset`과 비교한다.
- 능력치 카드의 `약점:` 줄과 약점 표시는 둘 다 **현재** `stats`로 계산하고, 별명 이름만 `initialStats`를 쓴다.
- `data-testid="nickname"`은 신원 카드 이름 자리 한 곳에만 둔다.
- 진행 도메인의 로그·연간 자산 검증은 `server/src/test/java/investorgame/api/GameFlowTest.java`에 단언을 더하는 방식으로 한다.
- 에이전트 배정(ownership.yml)이 아직 없으므로 한 브랜치에서 계약 → 서버 → 클라이언트 순으로 진행한다.
