# 2단계: 아주 작은 회사

> 설계: [증권사 육성 설계](../specs/2026-11-05-brokerage-raising-design.md) 4·6·7절
> 구현한 결정: [decisions.md](../../decisions.md) 208~212번
> 앞 단계: [1단계 3분 육성 한 판](./2026-11-05-stage1-raising-run.md)

## 흐름

```
첫 육성 → 입사 심사 → 1호 직원으로 등록 → 회사가 열림(F, 자리 2개, 시작 자본 = 그 판의 돈)
  └ 한 해: 연초 회의(폭락 조짐, 필요한 인재) → 배치 → (공채 육성: 회사 돈 10%) → 결산
  └ 세 해를 결산하면 체험 끝 → 새 회사 차리기
```

## 서버

- `raising_company.state`(JSON): 자본, 직원(이름·능력치·자리), 올해 시장 갈래(숨은 값)·조짐·필요한 자리, 공채 판, 결산 기록
- `CompanyEngine`: 회사 열기, 등급·자리, 연초 회의, 배치, 결산. DB와 시각을 모른다
- 공채 육성은 `POST /api/runs`가 맡는다: 회사가 돌고 있으면 운용금을 회사에서 꺼낸다
- 판정 확률은 행동 도메인의 `flipChanceBp`·`hintAccuracyPercent`로 육성과 같은 규칙을 쓴다

## 화면

- 입사 심사 결과: 회사가 없으면 "1호 직원으로 등록하고 회사를 연다", 있으면 등록 / 기존 직원과 바꾸기 / 돌려보내기
- 회사: 등급과 사다리, 자본과 다음 등급, 지난 결산(직원별 손익, 수수료, 소식 줄), 연초 회의, 직원별 자리 고르기, 공채 육성·결산 버튼

## 남은 것

- 육성과 회사가 같은 해·같은 시장 (6.2절)
- 큰 손실의 등급 하락 (6.4절), X 이상의 실전 경험과 효과 (2.3·2.4절)
- 인사 직원 (6.3절)
