# 아키텍처 설계

> 상태: v0.3 (증권사 육성 구조로 개정, 2026-11-05. #292에서 옛 인생 시뮬레이터 코드를 지운 뒤)
> 표기: **(확정)** = 대화에서 정해진 것, **(제안)** = 제 판단이며 아직 합의되지 않은 것. 게임 설계는 [증권사 육성 설계](./superpowers/specs/2026-11-05-brokerage-raising-design.md), 결정은 [decisions.md](./decisions.md) 197번부터, 요구사항은 [prd.md](./prd.md)를 따른다.

## 1. 전제

| 항목 | 내용 |
|---|---|
| 플랫폼 | 반응형 웹 + PWA (확정). PWA는 홈 화면 추가와 화면 자산 캐시 용도이며 오프라인 플레이는 지원하지 않는다 |
| 온라인 | **온라인 전용** (확정). 네트워크가 끊기면 게임이 진행되지 않는다 |
| 계산 주체 | 서버가 **능력치, 판정·형광펜, 카드 구성, 시장, 회사 결산**을 맡는다 (확정) |
| 시간 진행 | **시계가 없다** (확정, decisions.md 197·208번). 육성 판은 카드를 고를 때마다, 회사는 사장이 결산할 때마다 넘어간다 |
| 클라이언트 역할 | 화면 표시와 입력 전달. 능력치 점수·확률·숨은 값 등 규칙 정보를 알지 못한다 (확정) |
| 진행 상태 | 서버에 저장한다. 육성 판과 회사의 상태는 각각 JSON 한 칸이다 (decisions.md 198·208번) |
| 계정 | 없음. 익명 세션으로 육성 판과 회사를 묶는다 (확정) |
| 콘텐츠 | 직접 작성한 카드·뉴스·단서 문장·종목·위기를 서버가 소유하고 쓴다. 자동 생성은 하지 않는다 (확정) |
| 결과 저장 | 끝난 육성 판은 `raising_run`에 남는다. 관리자 플레이 기록에 쓴다 (decisions.md 219번) |
| 랭킹 | 없다. 지금은 생각하지 않는다 (증권사 육성 설계 1절). 옛 순위표는 #292에서 지웠다 (decisions.md 227번) |
| 한 판 | **육성 판은 카드 12장, 약 3분, 카드 수로 끝난다.** **회사는 한 해씩 도는 턴제**이고, 시대(세 해)가 끝나면 판다 (확정, decisions.md 197·208·215번) |

서버 계산의 효과: 능력치 점수, 뉴스의 숨은 방향, 판정 확률이 클라이언트에 노출되지 않는다. 화면에는 능력치의 **등급만** 나간다 (decisions.md 198·206번). 규칙이 서버 한 곳에만 있어 두 벌을 유지할 필요가 없다.

시계가 없는 이유: 나이 개념이 사라졌고, 판 하나를 20분에서 3분으로 줄였다 (증권사 육성 설계 1절). 카드 한 장이 시장의 한 분기라서 시간은 카드 수로 센다. 회사는 사장이 육성하는 동안 멋대로 움직이지 않는다 (설계 6.1절).

### 2.1 DB 규칙 (확정)

- **외래 키(FK)를 쓰지 않는다.** 테이블 사이의 연결은 ID 값으로만 두고, 정합성은 애플리케이션이 지킨다. 인덱스와 유니크 제약은 사용한다.
- **Flyway 방식의 마이그레이션.** 손으로 쓴 버전 SQL 파일(`V<번호>__<설명>.sql`)을 순서대로 적용한다. 이미 적용된 파일은 수정하지 않고, 변경은 새 버전을 추가한다.
- **DB 스키마는 하나만 쓴다.** MSA로 분리하는 것은 목표가 아니다 (확정).

구체안:

- 도메인은 **테이블 이름 접두사**로 자기 테이블을 구분한다. 예: `raising_run`, `session_info`. 접두사는 도메인 이름과 같다.
- 다른 도메인의 테이블을 읽거나 조인하지 않고, 필요하면 해당 도메인의 서비스 인터페이스를 호출한다. 스키마로 막을 수 없으므로 코드 규칙(ArchUnit)과 리뷰로 지킨다.
- Flyway 위치는 `db/migration` 하나다. 파일 이름에 도메인을 넣는다. 예: `V202611051000__raising_init.sql`.
- 버전 번호는 시각 기반(`yyyyMMddHHmm`)으로 쓰고, `MigrationRulesTest`가 번호 중복·FK·접두사를 검사한다.
- 병합 순서가 번호 순서와 어긋날 수 있어서 개발과 CI 환경은 Flyway의 `outOfOrder`를 켠다. 운영은 끈다 ([db.md](./db.md) 6절).
- JPA의 연관 관계 매핑과 스키마 자동 생성은 쓰지 않는다.
- 상태가 짧고 다른 도메인이 읽지 않으면 **JSON 한 칸(`jsonb`)에 통째로** 둔다. 육성 판과 회사가 그렇다 (decisions.md 198·208번).

## 3. 서버 도메인 구조

모듈형 모놀리스다. 한 프로젝트 안에서 패키지를 도메인별로 나누고, 도메인 경계를 어기면 빌드가 실패한다(`DomainBoundaryTest`). MSA 분리는 목표가 아니다 (확정). 다음 규칙을 지킨다.

1. 도메인은 자기 데이터를 단독 소유하고, 다른 도메인은 서비스 인터페이스로만 접근한다.
2. 도메인은 테이블 이름 접두사로 구분한다 (2.1절).
3. 도메인 사이는 ID로만 연결한다. FK는 없고, 다른 도메인의 테이블을 직접 조인하지 않는다.

### 도메인 목록

도메인은 넷이다. 상세는 [domains.md](./domains.md).

| 도메인 | 패키지 | 소유하는 상태 | 책임 |
|---|---|---|---|
| 육성 | `raising` | 육성 판, 세션의 육성 기억, 회사 | 3분 육성 한 판(카드 구성, 시장, 판정 조율, 입사 심사)과 회사(등록, 배치, 결산, 공채, 인사, 매각, 명성)를 조율한다 |
| 행동 | `behavior` | 없음 (순수 규칙) | 선택이 뒤집히는 판정(줏대 → 인내심/용기), 형광펜의 정답 여부(힌트), 운, 판정 한 번의 뒤집힘 확률 |
| 콘텐츠 | `content` | 콘텐츠 버전 기록 | `content/` JSON 로드·검증과 조회 |
| 세션 | `session` | 익명 세션 | 세션 발급과 확인, 최근 세션 목록(관리자) |

**도메인이 아닌 패키지**

| 패키지 | 내용 |
|---|---|
| `api` | 컨트롤러, 요청·응답 변환, 예외 처리, 관리자 토큰 확인, 플레이 로그(`investorgame.play`). 규칙을 판단하지 않는다 |
| `common` | 두 도메인 이상이 쓰는 값 타입(`Action`, `Direction`, `Sentiment`, `Stats`, `StatGrade`, `Hint`, `Deviation` 등), 시드 난수, 공통 예외 |
| `config` | Spring 설정 (기록용 `Clock`) |

**클라이언트 앱**은 도메인이 아니라 서버 API를 그리는 표현 계층이다 (7절).

### 호출 방향

```
api ─→ 세션 (확인, 관리자 세션 목록)
   └─→ 육성 ─→ 행동
             └→ 콘텐츠
```

`DomainBoundaryTest`가 지키는 규칙:

- **육성만 다른 도메인(행동·콘텐츠)을 쓴다.** 행동·콘텐츠·세션은 다른 도메인을 부르지 않는다.
- 어느 도메인도 다른 도메인의 `internal` 패키지를 쓰지 않는다.
- `api`는 육성과 세션의 공개 타입만 쓴다. 행동·콘텐츠를 직접 부르지 않는다.
- 도메인과 `common`은 `api`를 모른다. `common`은 어떤 도메인에도 의존하지 않는다.
- 행동은 상태가 없다. 능력치와 난수 생성기를 받아 결과를 돌려주는 순수 로직이다.

## 4. 시간 흐름: 카드와 해

실시간 시계는 없다. 서버는 요청을 받을 때만 계산한다.

**육성 판 (decisions.md 197번)**

- 판의 카드 순서는 설정 `raising.deck`이 정한다: 성향 2 → 실전 매매 뉴스 7 + 돈이 걸린 큰일 2(그중 하나는 빚내서 사기) → 입사 심사 1, 모두 12장. 투자 원칙 카드·풀기 카드는 뉴스 자리를 대신한다.
- **카드 한 장이 시장의 한 분기다.** 카드를 넘길 때마다 종목 가격이 움직인다 (decisions.md 205번).
- 서버가 지금 카드를 펼쳐 두고, 클라이언트는 그 카드 번호와 고른 선택을 보낸다. 카드 번호가 지금 카드와 다르면 400이다(두 번 누름, 늦은 요청).
- 고르면 서버가 판정 → 매매 → 가격 반영 → 성장을 처리하고, 결과 카드와 다음 카드를 함께 돌려준다.
- 화면에는 나이 대신 "수습 기간 n / 12"가 보인다. 마지막 입사 심사 카드에서 판이 끝난다.

**회사 (decisions.md 208번)**

- 한 해 = 연초 회의 → 배치 → 공채 육성(하고 싶을 때만) → 결산.
- **사장이 결산을 눌러야 해가 넘어간다.** 육성 판을 하는 동안 회사는 움직이지 않는다.
- 시대(세 해, `raising.company.turns`)가 끝나면 회사를 팔아야 다음 육성 판을 시작할 수 있다 (decisions.md 215번).

**공통**

- 요청마다 판(또는 회사) 행을 `SELECT ... FOR UPDATE`로 잠그고 한 트랜잭션에서 처리한다.
- 연결이 끊겨도 서버에서 흐르는 것이 없다. 재접속하면 `GET /api/runs/current`와 `GET /api/company`로 이어한다.
- 난수는 판·회사마다 서버가 시드를 만들고, 판단마다 시드와 키에서 하위 시드를 유도한다(`common.random`). 같은 시드와 같은 선택 순서면 같은 판이 재현되어 버그 재현과 밸런스 검증에 쓴다.
- 서버는 게임 계산에 현재 시각을 쓰지 않는다. `Clock`은 기록용 시각(`created_at`, 세션 만료)에만 쓴다.

> 기록: 옛 인생 시뮬레이터(15세 → 70세, 1배속 약 10~20분)는 클라이언트가 시계를 돌리고 `POST /api/games/{id}/advance`로 게임 시각을 보고했다. 서버는 그 구간의 월급·손익·이벤트를 계산하고 시각의 역행과 과도한 건너뛰기를 막았다. #292에서 코드를 지웠다 (decisions.md 227번).

## 5. API 개요

모든 경로는 `/api`로 시작한다. 계약의 원본은 `contracts/openapi/game.yaml`이다. 세션은 `IG_SESSION` 쿠키로 전달한다.

| 용도 | 요청 | 비고 |
|---|---|---|
| 세션 확보 (없으면 발급) | `POST /api/sessions` | |
| 육성 판 시작 | `POST /api/runs` | 진행 중인 판이 있으면 버리고 새로 시작한다. 회사가 돌고 있으면 공채 판이다 (decisions.md 212번) |
| 가장 최근 육성 판 | `GET /api/runs/current` | 진행 중이거나 끝난 판. 이어하기와 결과 보기 |
| 카드에 선택 내기 | `POST /api/runs/{runId}/choose` | 본문 `{card, option}`. 지나간 카드 번호거나 고를 수 없는 선택이면 400 |
| 가장 최근 회사 | `GET /api/company` | 돌고 있거나 끝난 회사 |
| 육성한 사람 등록·돌려보내기 | `POST /api/company/hires` | 회사가 없으면 등록하며 회사가 열린다. 자리가 꽉 찼으면 `replace`의 직원과 바꾼다 |
| 배치 | `POST /api/company/placement` | 직원 ID → 자리 코드(쉬면 null). 자리 수를 넘으면 400 |
| 결산 | `POST /api/company/settle` | 올해를 굴리고 다음 해 연초 회의로 간다 |
| 인사팀 공채 | `POST /api/company/hr-recruit` | 3분 육성 없이 신입을 데려온다 (decisions.md 223번) |
| 인사팀 신입 등록·돌려보내기 | `POST /api/company/candidate` | |
| 매각과 재창업 | `POST /api/company/sale` | 데려갈 공동창업자를 고른다. 응답은 새 회사다 (decisions.md 215~217번) |
| 관리자 플레이 기록 | `GET /api/admin/plays` | `X-Admin-Token` 헤더. 토큰 설정이 비어 있으면 꺼진다 (decisions.md 46·219번) |

- 클라이언트에는 능력치 점수, 확률, 숨은 방향, 올해 시장 갈래 같은 규칙 정보가 내려가지 않는다. 응답에는 화면에 필요한 값(등급, 카드 문구, 결과, 실제 행동과 원인)만 담는다.
- 서버 로그 `investorgame.play`에 육성 판의 시작·카드마다의 선택·끝, 회사의 등록·결산·매각이 IP와 함께 남는다.
- 옛 `/api/games/**`, 순위표, 결과 공유(`/r/{id}`, `/api/shares`), 봇 세션 API는 #292에서 지웠다 (decisions.md 227번).

## 6. 폴더 구조

```
backend/                          Spring Boot (Gradle)
  src/main/java/investorgame/
    InvestorGameApplication.java 진입점
    api/                         컨트롤러, 요청·응답 변환, 예외 처리 (규칙 판단 없음)
    config/                      Spring 설정
    common/                      도메인에 속하지 않는 공용 코드
      random/                    판 시드에서 하위 시드를 유도하는 코드
      error/                     공통 예외 타입
    raising/                     육성 (육성 판과 회사)
    behavior/  content/  session/
  src/main/resources/
    application.yml              규칙 수치(behavior.*, raising.*)도 여기 있다
    db/migration/                Flyway 마이그레이션 (한 폴더, 파일명에 도메인 표시)
  src/test/java/investorgame/
    <도메인>/                    도메인 단위·시뮬레이션 테스트
    api/                         API 통합 테스트
    architecture/                ArchUnit 경계 검사, 마이그레이션 규칙 검사
frontend/                         클라이언트 (React, Vite)
  src/features/raising/          육성 판·입사 심사·회사 화면, 사무실 그림
  src/features/game/             카드·맞대결 막대 같은 공용 화면 조각, 도트 사람 그림(pixel/)
  src/features/admin/            관리자 플레이 기록
  e2e/                           Playwright
contracts/openapi/                OpenAPI 명세
content/                          직접 작성한 콘텐츠 원본(JSON). 서버가 읽는다
docs/                             설계 문서
```

### 6.1 서버 패키지 규칙 (확정)

도메인 하나는 다음 구조를 가진다.

```
investorgame/raising/
  RaisingService.java      공개 인터페이스. 다른 도메인과 api가 호출하는 입구
  RunView.java ...         공개 입력·출력 record
  internal/                구현, 저장소, 상태. 다른 도메인이 import하면 빌드 실패
```

- **도메인 우선으로 나눈다.** `controller/service/repository` 같은 계층 폴더로 나누지 않는다.
- **`common`에는 두 도메인 이상이 실제로 쓰는 코드만 둔다.** "쓸 것 같다"는 이유로 넣지 않는다. 도메인 규칙과 게임 수치는 넣지 않는다.

## 7. 클라이언트 구조

- 시계가 없다. 사용자가 누르면 서버 API를 부르고 응답으로 화면을 그린다.
- 게임 규칙, 확률, 숨은 값을 클라이언트 코드에 두지 않는다. 능력치는 서버가 준 등급으로만 그린다.
- 카드·기사·소식 줄 같은 게임 문구는 서버가 콘텐츠에서 골라 보낸다. 버튼·안내·그림 같은 화면 문구는 클라이언트가 가진다.
- OpenAPI에서 생성한 타입과 API 클라이언트(`openapi-fetch`)를 쓴다. 상태는 `features/raising/store.ts`(Zustand) 하나에 둔다.
- **한 번에 한 모드만 보인다** (증권사 육성 설계 7.3절). 진행 중인 판이 있으면 카드, 끝났는데 등록을 정하지 않았으면 입사 심사 결과, 회사가 있으면 회사, 아무것도 없으면 시작 화면이다(`App.tsx`).
- 새로고침이나 재접속 시 세션 쿠키로 `GET /api/runs/current`와 `GET /api/company`를 불러 서버의 현재 상태에서 이어한다.
- 라우터가 없다. 주소가 `/admin`이면 관리자 플레이 기록, 나머지는 게임이다.
- 그림 끄기(decisions.md 190번)를 따른다. 끄면 같은 내용을 글로 보인다.

## 8. 에이전트 분업 (기록)

> 기록: 옛 인생 시뮬레이터를 처음 만들 때(2026-10) Orca 에이전트 다섯으로 나눈 분업이다. 그때의 도메인(캐릭터·자산·이벤트 운영·진행·결과 등)은 #292에서 지웠고, 지금 도메인(3절)에는 맞지 않는다. 남은 원칙만 적는다.

- 계약이 먼저다. `contracts`(OpenAPI)를 먼저 고치고 클라이언트 타입을 다시 만든다(`pnpm gen:api`). 계약은 통합 담당이 관리한다.
- 도메인 경계는 작업자 수와 무관하게 빌드에서 강제한다 (ArchUnit).
- 마이그레이션 파일은 그 테이블의 도메인 이름으로 만든다 ([db.md](./db.md) 6절).
- 각 작업은 자기 범위의 테스트를 직접 작성한다.

## 9. 코드 슬롭 방지

- 코드 스타일 문서([code-style.md](./code-style.md))를 공통 지침으로 둔다.
- 규칙 예: 요청되지 않은 추상화 금지, 데이터로 풀 수 있으면 코드로 분기하지 않기, 한 번만 쓰는 헬퍼 금지, 주석은 이유만 쓰기.
- 도메인 용어집([domains.md](./domains.md) 6절)으로 같은 개념에 이름이 여러 개 붙지 않게 한다.
