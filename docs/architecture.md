# 아키텍처 설계

> 상태: v0.3 (증권사 육성 구조로 개정, 2026-11-05. #292에서 옛 인생 시뮬레이터 코드를, decisions.md 228번에서 3분 육성 판을 지운 뒤)
> 표기: **(확정)** = 대화에서 정해진 것, **(제안)** = 제 판단이며 아직 합의되지 않은 것. 게임 설계는 [증권사 육성 설계](./superpowers/specs/2026-11-05-brokerage-raising-design.md), 결정은 [decisions.md](./decisions.md) 197번부터(228번부터가 지금 흐름), 요구사항은 [prd.md](./prd.md)를 따른다.

## 1. 전제

| 항목 | 내용 |
|---|---|
| 플랫폼 | 반응형 웹 + PWA (확정). PWA는 홈 화면 추가와 화면 자산 캐시 용도이며 오프라인 플레이는 지원하지 않는다 |
| 온라인 | **온라인 전용** (확정). 네트워크가 끊기면 게임이 진행되지 않는다 |
| 계산 주체 | 서버가 **능력치, 공채 시장, 시장 갈래, 투자 회의, 판정·형광펜, 결산**을 맡는다 (확정) |
| 시간 진행 | **시계도 나이도 없다** (확정, decisions.md 197·208번). 회사는 **한 분기씩 도는 턴제**다: 연초 회의(공채) → 분기마다 [배치 → 거시경제 회의 → (직원이 종목을 물어 오면) 종목 회의 → 분기 넘기기] × 4 → 연말 결산 (decisions.md 268번). 사장이 분기 넘기기를 눌러야 분기가 넘어간다 |
| 클라이언트 역할 | 화면 표시와 입력 전달. 능력치 점수·확률·숨은 값 등 규칙 정보를 알지 못한다 (확정) |
| 진행 상태 | 서버에 저장한다. 회사의 상태는 JSON 한 칸이다 (decisions.md 208번) |
| 계정 | 없음. 익명 세션으로 회사와 사장의 명성을 묶는다 (확정) |
| 콘텐츠 | 직접 작성한 뉴스·단서 문장·종목·위기·회사 문구를 서버가 소유하고 쓴다. 자동 생성은 하지 않는다 (확정) |
| 결과 저장 | 끝난 회사는 `raising_company`에 남는다. 관리자 플레이 기록에 쓴다 (decisions.md 228번) |
| 랭킹 | 없다. 지금은 생각하지 않는다 (증권사 육성 설계 1절). 옛 순위표는 #292에서 지웠다 (decisions.md 227번) |
| 한 판 | 회사 하나가 해마다 이어진다. 시대가 끝나도 멈추지 않는다. 매각과 재창업(215번)은 뺐다 (decisions.md 236번) |

서버 계산의 효과: 능력치 점수, 시장 갈래, 투자 회의의 숨은 방향, 판정 확률이 클라이언트에 노출되지 않는다. 화면에는 능력치의 **등급만** 나간다 (decisions.md 206번). 규칙이 서버 한 곳에만 있어 두 벌을 유지할 필요가 없다.

시계가 없는 이유: 나이 개념이 사라졌고(증권사 육성 설계 1절), 회사는 사장이 누를 때만 움직이는 턴제다(설계 6.1절). 3분 육성 판도 카드 수로 끝나는 판이었고, 228번에서 없앴다.

### 2.1 DB 규칙 (확정)

- **외래 키(FK)를 쓰지 않는다.** 테이블 사이의 연결은 ID 값으로만 두고, 정합성은 애플리케이션이 지킨다. 인덱스와 유니크 제약은 사용한다.
- **Flyway 방식의 마이그레이션.** 손으로 쓴 버전 SQL 파일(`V<번호>__<설명>.sql`)을 순서대로 적용한다. 이미 적용된 파일은 수정하지 않고, 변경은 새 버전을 추가한다.
- **DB 스키마는 하나만 쓴다.** MSA로 분리하는 것은 목표가 아니다 (확정).

구체안:

- 도메인은 **테이블 이름 접두사**로 자기 테이블을 구분한다. 예: `raising_company`, `session_info`. 접두사는 도메인 이름과 같다.
- 다른 도메인의 테이블을 읽거나 조인하지 않고, 필요하면 해당 도메인의 서비스 인터페이스를 호출한다. 스키마로 막을 수 없으므로 코드 규칙(ArchUnit)과 리뷰로 지킨다.
- Flyway 위치는 `db/migration` 하나다. 파일 이름에 도메인을 넣는다. 예: `V202611051100__raising_company.sql`.
- 버전 번호는 시각 기반(`yyyyMMddHHmm`)으로 쓰고, `MigrationRulesTest`가 번호 중복·FK·접두사를 검사한다.
- 병합 순서가 번호 순서와 어긋날 수 있어서 개발과 CI 환경은 Flyway의 `outOfOrder`를 켠다. 운영은 끈다 ([db.md](./db.md) 6절).
- JPA의 연관 관계 매핑과 스키마 자동 생성은 쓰지 않는다.
- 상태가 짧고 다른 도메인이 읽지 않으면 **JSON 한 칸(`jsonb`)에 통째로** 둔다. 회사와 사장의 기억이 그렇다 (decisions.md 198·208번).
- 옛 테이블과 `raising_run`은 DB에 남아 있지만 코드가 쓰지 않는다 ([db.md](./db.md) 2.2절, decisions.md 227·228번).

## 3. 서버 도메인 구조

모듈형 모놀리스다. 한 프로젝트 안에서 패키지를 도메인별로 나누고, 도메인 경계를 어기면 빌드가 실패한다(`DomainBoundaryTest`). MSA 분리는 목표가 아니다 (확정). 다음 규칙을 지킨다.

1. 도메인은 자기 데이터를 단독 소유하고, 다른 도메인은 서비스 인터페이스로만 접근한다.
2. 도메인은 테이블 이름 접두사로 구분한다 (2.1절).
3. 도메인 사이는 ID로만 연결한다. FK는 없고, 다른 도메인의 테이블을 직접 조인하지 않는다.

### 도메인 목록

도메인은 넷이다. 상세는 [domains.md](./domains.md).

| 도메인 | 패키지 | 소유하는 상태 | 책임 |
|---|---|---|---|
| 육성 | `raising` | 회사, 세션의 기억(사장 명성) | 증권사를 조율한다: 차리기, 공채 시장, 배치, 투자 회의, 결산 (매각·명성 규칙은 엔진에 남아 있지만 API가 부르지 않는다, 236번) |
| 행동 | `behavior` | 없음 (순수 규칙) | 판정 한 번의 뒤집힘 확률, 안목의 정답률과 힌트(형광펜) |
| 콘텐츠 | `content` | 콘텐츠 버전 기록 | `content/` JSON 로드·검증과 조회 |
| 세션 | `session` | 익명 세션 | 세션 발급과 확인, 최근 세션 목록(관리자) |

**도메인이 아닌 패키지**

| 패키지 | 내용 |
|---|---|
| `api` | 컨트롤러, 요청·응답 변환, 예외 처리, 관리자 토큰 확인, 플레이 로그(`investorgame.play`). 규칙을 판단하지 않는다 |
| `common` | 두 도메인 이상이 쓰는 값 타입(`Action`, `Direction`, `Sentiment`, `Stats`, `StatCodes`, `StatGrade`, `Hint`, `Deviation` 등), 한국어 문구 채우기(`Korean`), 시드 난수, 공통 예외 |
| `config` | Spring 설정 (기록용 `Clock`) |

**클라이언트 앱**은 도메인이 아니라 서버 API를 그리는 표현 계층이다 (7절).

### 호출 방향

```
api ─→ 세션 (확인, 관리자 세션 목록)
   └─→ 육성 ─→ 행동
             └→ 콘텐츠
```

`DomainBoundaryTest`가 지키는 규칙:

- **육성만 다른 도메인(행동·콘텐츠)을 쓴다.** 행동·콘텐츠·세션은 다른 도메인을 부르지 않는다.
- 어느 도메인도 다른 도메인의 `internal` 패키지를 쓰지 않는다.
- `api`는 육성과 세션의 공개 타입만 쓴다. 행동·콘텐츠를 직접 부르지 않는다.
- 도메인과 `common`은 `api`를 모른다. `common`은 어떤 도메인에도 의존하지 않는다.
- 행동은 상태가 없다. 능력치와 난수 생성기를 받아 결과를 돌려주는 순수 로직이다.

## 4. 시간 흐름: 해와 턴

실시간으로 흐르는 것은 없다. 서버는 요청을 받을 때만 계산한다.

**회사의 한 해 (decisions.md 228~231번)**

1. **연초 회의**: 해가 시작될 때 서버가 올해 시장 갈래(숨은 값)와 폭락 조짐, 올해 필요한 자리, 공채 시장의 지원자, 투자 회의의 기사를 미리 정해 둔다. 화면은 조짐과 필요한 인재만 보인다.
2. **공채·배치**: 사장이 계약금을 내고 지원자를 뽑거나(몇 명이든), 값을 내고 지원자를 새로 받고, 직원을 자리에 앉힌다. 순서는 자유다.
3. **거시경제 회의와 종목 회의** (decisions.md 266·267번): 결산을 누르면 거시경제 회의에서 올해 회사의 태도(공격·중립·방어)를 고른다. 그 뒤 직원이 종목을 물어 오면 종목 회의를 결산 전에 해야 한다. 사장이 산다·판다·지켜본다를 고르면 직원마다 사장 말대로 하거나 제멋대로 하고, 손익이 바로 자본에 들어간다.
4. **결산**: 직원들이 배치대로 한 해를 굴린 결과를 낸다. 해가 넘어가고 다음 해 연초 회의가 준비된다. 회사는 끝나지 않는다(236번).

- 처음에는 회사가 없다. `POST /api/company`가 사장의 사재 1억 원으로 직원 없이 차린다 (decisions.md 228번).
- 매각을 빼기 전에 시대가 끝나 멈춘 회사는 `GET /api/company`가 다음 해 연초 회의부터 다시 연다 (236번).

**공통**

- 요청마다 회사 행을 `SELECT ... FOR UPDATE`로 잠그고 한 트랜잭션에서 처리한다 ([db.md](./db.md) 5절).
- 연결이 끊겨도 서버에서 흐르는 것이 없다. 재접속하면 `GET /api/company`로 이어한다.
- 난수는 회사마다 서버가 시드를 만들고, 판단마다 시드와 키(해, 직원 ID 등)에서 하위 시드를 유도한다(`common.random`). 같은 시드와 같은 선택 순서면 같은 회사가 재현되어 버그 재현과 밸런스 검증에 쓴다.
- 서버는 게임 계산에 현재 시각을 쓰지 않는다. `Clock`은 기록용 시각(`created_at`, 세션 만료)에만 쓴다.

> 기록: 옛 인생 시뮬레이터(15세 → 70세, 1배속 약 10~20분)는 클라이언트가 시계를 돌리고 `POST /api/games/{id}/advance`로 게임 시각을 보고했다. #292에서 코드를 지웠다 (decisions.md 227번). 그 뒤의 3분 육성 판은 카드 한 장이 시장의 한 분기였고 카드 12장으로 끝났다(`/api/runs`). 228번에서 지웠다.

## 5. API 개요

모든 경로는 `/api`로 시작한다. 계약의 원본은 `contracts/openapi/game.yaml`이다. 세션은 `IG_SESSION` 쿠키로 전달한다.

| 용도 | 요청 | 비고 |
|---|---|---|
| 세션 확보 (없으면 발급) | `POST /api/sessions` | |
| 가장 최근 회사 | `GET /api/company` | 돌고 있거나 끝난 회사. 없으면 404 |
| 회사 차리기 | `POST /api/company` | 사장의 사재로 회사를 연다. 이미 회사가 있으면 400(회사는 세션마다 하나). 가장 최근 회사가 망했으면(`broke`) 닫고 다음 번호로 연다 (247번) |
| 지원자 뽑기 | `POST /api/company/hires` | 본문 `{applicantId, replace}`. 계약금을 낸다. 자리가 꽉 찼으면 `replace`의 직원을 내보낸다. 없는 지원자, 모자란 돈이면 400 |
| 지원자 새로 받기 | `POST /api/company/applicants/refresh` `{year, refreshes}` | 값을 내고 올해 지원자를 새로 받는다. 이미 한 것이면 지금 회사를 그대로 돌려준다 (254번) |
| 배치 | `POST /api/company/placement` | 직원 ID → 자리 코드(쉬면 null). 자리 수를 넘거나 같은 직원이 두 번 오면 400 |
| 이직 제안 | `POST /api/company/poach` `{keep}` | 남기거나 보낸다(이적료). 답하지 않아도 직원은 남는다. 제안이 없으면 400 (262·265번) |
| 거시경제 회의 열기 | `POST /api/company/macro/open` | 지금 배치로 직원 한마디와 형광펜을 굳힌다. 이미 열었으면 그대로 (266번) |
| 거시경제 회의 | `POST /api/company/macro` | 본문 `{stance}`: `AGGRESSIVE`·`NEUTRAL`·`DEFENSIVE`. 그해 결산 판돈에 걸린다. 고르면 직원이 종목을 물어 올 수 있다(267번). 이미 골랐으면 400 |
| 종목 회의 열기 | `POST /api/company/invest/open` | 지금 배치로 직원 한마디와 형광펜을 굳힌다. 이미 열었으면 그대로 (249번) |
| 종목 회의 | `POST /api/company/invest` | 직원이 종목을 물어 왔을 때만(267번). 본문 `{choice, big}`: `BUY`·`SELL`·`HOLD`, 크게(260번). 이미 했거나 돈을 굴리는 직원이 없으면 400 (decisions.md 229번) |
| 분기 넘기기 | `POST /api/company/settle` `{year, quarter}` | 한 분기를 굴리고 다음 분기로 간다. 4분기면 연말 결산을 하고 다음 해 연초 회의로 간다(268번). 열 수 있는 종목 회의를 안 했으면 400. 이미 넘긴 분기면 지금 회사를 그대로 돌려준다(234번) |
| 관리자 플레이 기록 | `GET /api/admin/plays` | `X-Admin-Token` 헤더. 토큰 설정이 비어 있으면 꺼진다. 세션과 회사 목록 (decisions.md 46·228번) |

- 회사 요청의 응답은 모두 회사 전체(`Company`)다. 화면은 받은 회사로 다시 그린다.
- 클라이언트에는 능력치 점수, 확률, 올해 시장 갈래, 투자 회의의 숨은 방향 같은 규칙 정보가 내려가지 않는다. 응답에는 화면에 필요한 값(등급, 기사 문장, 형광펜 위치, 직원의 한마디와 고집, 결과와 원인)만 담는다.
- 서버 로그 `investorgame.play`에 회사의 차림·뽑기·투자 회의·결산이 IP와 함께 남는다.
- 옛 `/api/games/**`, 순위표, 결과 공유(`/r/{id}`, `/api/shares`), 봇 세션 API는 #292에서(decisions.md 227번), 육성 판 `/api/runs/**`와 인사팀 공채(`hr-recruit`, `candidate`)는 228번에서 지웠다.

### 6.1 서버 패키지 규칙 (확정)

도메인 하나는 다음 구조를 가진다.

```
investorgame/raising/
  CompanyService.java      공개 인터페이스. 다른 도메인과 api가 호출하는 입구
  CompanyView.java ...     공개 입력·출력 record
  internal/                구현, 저장소, 상태. 다른 도메인이 import하면 빌드 실패
```

- **도메인 우선으로 나눈다.** `controller/service/repository` 같은 계층 폴더로 나누지 않는다.
- **`common`에는 두 도메인 이상이 실제로 쓰는 코드만 둔다.** "쓸 것 같다"는 이유로 넣지 않는다. 도메인 규칙과 게임 수치는 넣지 않는다.

## 7. 클라이언트 구조

- 시계가 없다. 사용자가 누르면 서버 API를 부르고 응답으로 화면을 그린다.
- 게임 규칙, 확률, 숨은 값을 클라이언트 코드에 두지 않는다. 능력치는 서버가 준 등급으로만 그린다. 자동 배치(decisions.md 232번)도 화면에 보이는 등급으로만 견주고, 서버에는 보통 배치처럼 보낸다.
- 기사·한마디·소식 줄 같은 게임 문구는 서버가 콘텐츠에서 골라 보낸다. 버튼·안내·그림 같은 화면 문구는 클라이언트가 가진다.
- OpenAPI에서 생성한 타입과 API 클라이언트(`openapi-fetch`)를 쓴다. 상태는 `features/raising/store.ts`(Zustand) 하나에 둔다.
- 회사가 있으면 회사 화면, 없으면 회사를 차리는 시작 화면이다(`App.tsx`). 회사 화면 위쪽(등급·자본·건물 그림)은 늘 보이고, 아래는 **연초 회의 · 공채 · 배치 · 지난 결산** 탭으로 나뉜다. 결산 버튼은 화면 아래에 붙어 있고, 투자 회의는 결산을 누르면 화면 가운데 창으로 뜬다 (decisions.md 230·231번).
- 새로고침이나 재접속 시 세션 쿠키로 `GET /api/company`를 불러 서버의 현재 상태에서 이어한다.
- 라우터가 없다. 주소가 `/admin`이면 관리자 플레이 기록, 나머지는 게임이다.
- 그림 끄기(decisions.md 190번)를 따른다. 끄면 같은 내용을 글로 보인다. 이 설정만 브라우저에 둔다.

## 8. 에이전트 분업 (기록)

> 기록: 옛 인생 시뮬레이터를 처음 만들 때(2026-10) Orca 에이전트 다섯으로 나눈 분업이다. 그때의 도메인(캐릭터·자산·이벤트 운영·진행·결과 등)은 #292에서 지웠고, 지금 도메인(3절)에는 맞지 않는다. 남은 원칙만 적는다.

- 계약이 먼저다. `contracts`(OpenAPI)를 먼저 고치고 클라이언트 타입을 다시 만든다(`pnpm gen:api`). 계약은 통합 담당이 관리한다.
- 도메인 경계는 작업자 수와 무관하게 빌드에서 강제한다 (ArchUnit).
- 마이그레이션 파일은 그 테이블의 도메인 이름으로 만든다 ([db.md](./db.md) 6절).
- 각 작업은 자기 범위의 테스트를 직접 작성한다.

## 9. 코드 슬롭 방지

- 코드 스타일 문서([code-style.md](./code-style.md))를 공통 지침으로 둔다.
- 규칙 예: 요청되지 않은 추상화 금지, 데이터로 풀 수 있으면 코드로 분기하지 않기, 한 번만 쓰는 헬퍼 금지, 주석은 이유만 쓰기.
- 도메인 용어집([domains.md](./domains.md) 6절)으로 같은 개념에 이름이 여러 개 붙지 않게 한다.
