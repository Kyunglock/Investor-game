# 결정 기록

> 미결정이던 항목에 대한 결정과 남은 질문을 한 곳에 모은 문서다. 각 문서(`prd.md`, `architecture.md`, `domains.md`, `db.md`, `code-style.md`)의 미결정 표보다 이 문서가 최신이다.
> 표기: **(확정)** = 사용자가 정한 것, **(추천 수용)** = 제가 추천안을 냈고 사용자가 "추천대로"라고 한 것, **(제안)** = 아직 확인받지 않은 제 제안.

## 1. 게임 규칙

| # | 항목 | 결정 |
|---|---|---|
| 1 | 능력치 성장 방식 | **경험치와 자기계발 이벤트를 모두 쓰고, 성장 루트를 다양하게 둔다** (확정). 루트별 규칙은 캐릭터 스펙에서 정한다. 운은 성장하지 않는다 (확정, 이전) |
| 2 | 시작·종료 나이, 시간 속도 | **1세에 태어나 65세에 끝난다** (확정, 처음의 25세 시작을 바꿈). **성장기는 이벤트가 적어 빨리 흐른다** (확정): 성장기 1년 4초, 성인기 1년 12초로 한 판 약 9분 40초 (수치는 제안, 설정값) |
| 3 | 이벤트 구성 | **투자 스타일(장기 / 단기)에 따라 이벤트가 달라진다** (확정). 이를 위해 캐릭터에 `investment_style`을 둔다 (db.md 3.3절). 영향은 다음과 같다 (제안안을 사용자가 수용): **단기는 뉴스가 더 자주 나오고 변동이 크다. 장기는 뉴스가 드물고 연결 뉴스가 더 깊다.** 시각 보고 구간은 아래 "시각 보고(제안)" 참고 |
| 4 | 직업과 월급 | **직업은 캐릭터가 가진다** (확정). **직업에 따라 월급이 다르고, 연차가 오르면 연봉도 오른다** (확정). 캐릭터에 `job_start_day`를 둬서 연차를 계산한다. 직업별 월급과 상승 곡선은 콘텐츠로 정의한다. **이직은 불가능하다** (확정). 따라서 직업 선택 이벤트는 판당 한 번이고 `job_start_day`는 바뀌지 않는다 (추정) |
| 5 | 투자 성향 이벤트 | **어떤 상황을 주고 사용자가 어떻게 행동하는지로 판단한다** (확정). 이 결과로 투자 스타일과 관심 섹터가 정해진다. **성향 이벤트의 선택은 판정으로 뒤집지 않는다** (확정). 순수한 선택으로만 판단한다 |
| 6 | 투자 시작 전환 | **사용자 수락으로 시작한다** (확정). **월급을 받기 시작한 이후부터 투자를 시작할지 묻는다** (확정). **수락하지 않으면 저축 단계(`SAVING`)에 머문다** (확정). **거절하면 게임 속 1년마다 다시 묻는다** (확정). **투자 스타일이 확정된 뒤에만 묻는다** (확정). 제안은 선택형 이벤트(`OFFER`)로 다루고 단계 코드를 따로 늘리지 않는다 (제안) |
| 7 | 단계 코드 | **필요하다** (확정). 투자 시작 전(`SAVING`)과 후(`INVESTING`)의 이벤트가 달라진다 |
| 8 | 뉴스의 연결 | **뉴스끼리 깊이(depth)로 엮이고 여러 갈래가 있다** (확정). `event_instance`에 연결 필드를 둔다 (db.md 3.9절). **갈래는 사용자의 행동에 따라 갈린다** (확정). **판정을 거친 실제 행동으로 갈린다** (추천 수용). 이탈이 이후 이야기에 영향을 준다 |

### 시각 보고 (제안)

시각 보고의 구간 크기는 사용자가 정하지 않았다. 호출이 너무 잦아지지 않도록 다음을 제안한다.

- 서버가 응답에 **다음 이벤트가 발생하는 게임 시각**(`nextEventDay`)을 담아 준다.
- 클라이언트는 그 시각에 도달할 때 보고한다. 이벤트가 없어도 월급·주가 갱신을 위해 **최대 N초마다** 보고한다. N은 설정값이며 기본 5초를 가정한다.
- 한 번에 건너뛸 수 있는 상한은 N초에 해당하는 게임 시간의 몇 배로 정한다.
